## 精读

### 1. Do Similarity Measures Measure Similarity? How User Activity Creates Phantom Correlation

`2610.35765` · cs.IR · [abs](https://arxiv.org/abs/2610.35765) · [code](https://github.com/Mfavier91/Phantom-Correlation)

**一句话**：item-item 相似度里有一大块根本不是「共同偏好」，而是用户活跃度差异造出来的伪相关（phantom correlation）。哪怕所有用户完全独立地消费、只有总消费量不同，标准相似度度量照样会报出很强的 item 关联。

**为什么重要**：i2i 召回、协同过滤、图 embedding、对比学习正样本，全都建立在「共同消费 ≈ 共同偏好」上。这篇文章用最小假设证明，这个假设在用户活跃度异质时是系统性偏的——而且偏的方向和活跃度分布绑定，不是随机噪声。

**能拿走什么**：做 i2i 之前先按用户活跃度分层，看相关性还剩多少；低活用户的行为权重需要显式处理，而不是丢给 IDF 之类的启发式。

### 2. Preserving rare-item recall under a storage budget

`2610.36267` · cs.IR · [abs](https://arxiv.org/abs/2610.36267)

**一句话**：在固定 embedding 存储预算下，rank-300 的 4-bit 量化分解只用 13% 的教师存储，却保住了 95–103% 的长尾 recall@20 和 93–97% 的 NDCG@20；而**维度更低的全精度模型（rank-40）在每一个数据集上长尾召回都是最差的**。

**为什么重要**：工程直觉通常是「降维比降精度更安全」，这篇的结果正好反过来。7 个 dataset-backbone 组合、候选集事先固定、测试集只评一次，实验纪律比多数推荐论文严谨。

**能拿走什么**：如果线上受限于 embedding 存储，优先考虑「高秩 + 低比特」而不是「低秩 + 高精度」；同时别用教师保真度（teacher fidelity）当长尾指标，两者在这篇里并不同向。

### 3. AutoRSE: Evaluating LLM Agents as Recommendation Engineers

`2610.37228` · cs.IR · [abs](https://arxiv.org/abs/2610.37228) · [code](https://github.com/Ray-Tiann/AutoRSE)

**一句话**：让 LLM agent 自主改进推荐算法，在 6 个工业级推荐任务上 5 个有提升，平均相对提升 16.1%——但轨迹级分析显示，它们本质上是**工程优化器而不是算法改进者**，收益主要来自调参、改训练配方这类操作。

**为什么重要**：这是目前对「AutoML / agent 自动做推荐研究」最像样的一次系统评估（3 个前沿 LLM × 3 套 agent harness）。结论对两类人都有用：想用 agent 替代调参人力的人，和担心被替代的人。

**能拿走什么**：短期内把 agent 当「不知疲倦的调参工」是对的投资；指望它提出新的建模范式，目前证据不支持。

### 4. LESSRec: Level-Specific History Modeling for Semantic ID-Based Recommendation

`2610.37286` · cs.IR · [abs](https://arxiv.org/abs/2610.37286)

**一句话**：生成式推荐按粗到细逐层生成 semantic ID 时，历史里**只有和目标 token 同一语义层级的那些 token 真正有用**，其他层级是干扰；按层级分别编码历史、并只让解码器 attends 到对齐层级，效果更好。

**为什么重要**：这是一篇「先做推理期分析、再提方法」的论文，结论简单到近乎朴素，但直接指向了现有 SID 模型的一个结构性浪费。工程上改造成本低（改 attention mask + 加一路 item-level 序列）。

**能拿走什么**：检查你自己的 SID 解码器，历史是不是把 3 层 token 平铺在一起做 full attention——是的话，这里大概率有免费收益。

### 5. Compote: Collapse-Resistant Multiple Hypothesis Learning for Sequential Recommendation

`2610.37005` · cs.LG · cs.IR · [abs](https://arxiv.org/abs/2610.37005)

**一句话**：next-item 预测本质上是不确定的（同一段历史可以有多个合理延续），标准序列推荐把它压成单一预测。Compote 用多个 hypothesis + 「均匀监督 → winner-takes-all」的退火目标，强行让不同 hypothesis specialization 到不同 catalog 区域，并给了理论：最优解按最大熵量化原则划分条件分布，pooled score 仍保持 Bayes 最优排序。

**为什么重要**：多假设/多意图不是新想法，但同时给出「防坍缩机制 + 理论刻画 + 泛化界」的不多，而且推理时用的是无 normalizer 的 max-similarity，成本可控。

**能拿走什么**：如果你在做多意图召回或多样性排序，winner-takes-all 退火这一步是防坍缩的关键，比在 loss 里加 diversity 正则更干净。

### 6. Agent Memory as Recommendation: Recommender-System Design for Long-Term Memory of LLM Agents

`2610.34673` · cs.IR · cs.AI · cs.CL · [abs](https://arxiv.org/abs/2610.34673)

**一句话**：LLM agent 的长期记忆检索，本质上是「把请求当 user、把记忆当 item、把 context window 当 slate」的**预算受限的 slate 推荐问题**。作者把各家 memory 系统统一到一个 recommender cascade 的设计空间里，并把准确率分解成每一级各自控制的 completeness。

**为什么重要**：视角迁移做得干净。现在做 memory 的人基本各造各的轮子（几百到几千次 LLM call 建笔记/图），没人说清楚哪个组件真正贡献了准确率；用推荐系统的语言一套，级联设计、预算分配、评估口径立刻就有了共同坐标系。

**能拿走什么**：做 agent memory 的话，先按 cascade 拆你的 pipeline，逐级量 completeness，通常能发现瓶颈不在你以为的那一层。
